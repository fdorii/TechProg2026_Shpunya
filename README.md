## 1 Задача на выполнение - <code>Сервер несколько клиентов</code>

Для выполнения этого задания в исходной конфигурации сервера в файле <code>mytcpserver.cpp</code> и <code>mytcpserver.h</code> были выполнены некоторые изменения:
1. В .h:

    - Убран одиночный <code>mTcpSocket *</code>
    - Добавлен <code>QList<QTcpSocket*> mClients</code> — список всех подключённых клиентов
    - Добавлен <code>QMap<QTcpSocket*, QString> mBuffers</code> — отдельный буфер данных для каждого клиента

2. В .cpp:

    - <code>slotNewConnection()</code> — каждый новый сокет добавляется в список, сигналы подключаются к тем же слотам
    - <code>slotServerRead() и slotClientDisconnected()</code> — используют <code>sender()</code>, чтобы определить, от какого именно клиента пришёл сигнал. Это ключевой момент для многопользовательности
    - При отключении клиент удаляется из списка и буфера, вызывается <code>deleteLater()</code> для безопасного освобождения памяти

## 2 Задача на выполнение - <code>Docker</code>
1. Dockerfile — переписан с нуля:
    
    - Зафиксирована версия ubuntu:22.04 вместо ubuntu (latest) — для воспроизводимых сборок
    - Добавлен недостающий пакет libqt5sql5-sqlite — без него драйвер QSQLITE не загружается и БД не открывается, несмотря на успешную компиляцию
    - Добавлен multi-stage build: стадия builder компилирует проект со всеми инструментами, стадия runtime содержит только готовый бинарник и минимальные runtime-библиотеки — итоговый образ значительно легче
2. mytcpserver.cpp — исправлена логика чтения в slotServerRead(). Два бага, которые вместе ломали многопользовательность:
    - readAll() возвращает весь чанк целиком, например "auth user pass\x01" — поэтому проверка array == "\x01" никогда не срабатывала, маркер конца команды не обнаруживался
    - блок после цикла while парсил и очищал буфер без маркера, то есть немедленно при любых входящих данных
